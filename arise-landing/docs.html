Unlock ARISE's Full Potential

ARISE is a modular, YAML-driven CLI for bootstrapping production-ready Flutter projects and scaffolding consistent features across your entire lifecycle.

01 · Quick Start

Activate ARISE globally from pub.dev and run the interactive project wizard:

dart pub global activate arise
arise create

Only the project name is required. Every module is optional, and your choices are persisted in .arise.yaml at the project root so future commands stay aligned with your stack.

02 · Supported Stack

Choose any combination of built-in modules during setup or add them later:

Category Options
Architecture clean, mvvm, mvc, mvp, none
State Management riverpod, bloc, provider, getx, none
Routing go_router, auto_route, none
Networking dio, none
Dependency Injection get_it, injectable, none
Local Storage shared_preferences, none
Linting very_good_analysis, none

03 · arise create & Non-Interactive Flags

Skip the interactive prompts in scripts, team templates, or CI by passing configuration flags directly. ARISE creates the Flutter project, wires starter files (lib/main.dart, lib/app.dart, lib/core/), installs dependencies, runs codegen hooks (such as build_runner), and writes .arise.yaml. 

arise create my_app \
  --arch clean \
  --state riverpod \
  --route go_router \
  --network dio \
  --di get_it \
  --storage shared_preferences \
  --lint very_good_analysis

Short flags: -a (--arch), -r (--route), -n (--network). To generate a standard Flutter project without Arise modules, run arise create --skip my_app.

04 · Feature Scaffolding

Run arise gen feature from your project root (where .arise.yaml lives). ARISE reads your active architecture and state management to generate matching layers under lib/features/<name>/. 

arise gen feature auth            # standard (default)
arise gen feature auth -t minimal  # empty layer folders only
arise gen feature auth -t full     # complete feature + unit test
-t minimal

Empty architecture layer folders (e.g. data/, domain/, presentation/) with .gitkeep.

-t standard

Starter Dart classes per layer (Entity, Repository, Page) plus state files (Notifier, Bloc, Provider, or Controller).

-t full

Everything in standard plus Model (fromJson/toJson), Remote DataSource, UseCase, Widget, and unit test.

Names are normalized automatically (User-Profile → lib/features/user_profile/). Use --force (-f) to overwrite or --list (-l) to inspect templates.

05 · arise add, info & doctor

Extend an existing project or audit your environment health at any time:

arise add dio             # built-in module: adds DioClient, installs dio, updates .arise.yaml
arise add intl            # pub.dev package: runs flutter pub add intl
arise add -d mockito      # pub.dev dev dependency
arise add --list          # list all built-in Arise modules

arise info                # show .arise.yaml config and detected features
arise doctor              # check Dart SDK, Flutter SDK, templates & .arise.yaml

06 · Architecture & Custom Modules

ARISE decouples CLI commands from template details using a modular pipeline: Command → Wizard → TemplateRegistry → TemplateLoader → TemplateMerger → TemplateService.

Each built-in integration lives under templates/modules/<category>/<name>/ with a config.yaml and an optional files/ directory mirroring the target Flutter project structure: 

name: Riverpod
folders: []
packages:
  - name: flutter_riverpod
